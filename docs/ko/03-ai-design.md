# 03. AI 설계 — 「AI는 준비하고, 사람은 판단한다」

[← README](../../README.ko.md)

업무 시스템의 AI는 틀릴 수 있다는 전제에서 시작했습니다. 목표는 **AI가 틀려도 잘못된 데이터가 남지 않는 구조**입니다.

## 1. AI 에이전트

```
사용자 → 자연어 → LLM(의도 · Tool 선택) → Tool(서버 코드) → 기존 업무 로직 → DB
```

### 지키는 선

| 하지 않는 것 | 대신 |
|---|---|
| LLM이 SQL을 만든다 | 미리 정의된 Tool의 `run()`만 조회를 실행 |
| LLM이 DB를 고친다 | 쓰기 Tool은 서버가 실행하지 않음. 화면에 확인 창 → **기존 접수 함수**가 실행 |
| 프롬프트로 권한을 지킨다 | Tool 실행 전에 서버가 **세션으로** 판정 |
| LLM이 필수값을 지어낸다 | 빠진 값은 되묻게 함. 최종 관문은 화면의 등록 검증 함수 |
| 자율 무한 반복 | 메시지 한 번에 **LLM 호출 최대 2회, Tool 최대 3개** |

### 「필수값」이 두 곳에 있는 이유 (의도한 중복)
서버 쪽 필수값 목록은 LLM이 **질문을 잘 하게 하는 힌트**이고, 화면 쪽 검증 함수는 **실제 관문**입니다. 둘이 어긋나면 관문이 이깁니다 — 질문이 한 번 더 나갈 뿐, 빠진 값이 등록되는 일은 생기지 않습니다. 필수값의 정본은 화면 쪽 명세 파일 하나입니다.

### Tool (31종)
| 묶음 | 예 |
|---|---|
| 조회 | ECN 검색 · 상세 · 결재 현황 · 적용 대기 · 반복 변경 부품 · 모델 · 문서 검색 · 월간 추진 현황 · 프로젝트 검색 |
| 문서 질의 | 문서 **내용**에 대한 질문 · 절차서 근거 답변 · 작성 가이드 · 메뉴 도움말 · 사용자 매뉴얼 |
| 쓰기(확인 후) | ECN 접수 · 적용대상 지정 · 프로젝트 등록 · 기안 품의 초안 · 결재 · 개인 일정 |
| 추천 | 결재선 추천 · 비슷한 과거 건 · 재상신 도우미 |
| 화면 | 화면 열기 · 포털 열기 · 권한 조회/변경(관리자) |

### 공급자 한 겹
LLM 공급자는 운영 중 외부 API → 사내 게이트웨이로 바뀌었습니다. 그때 화면 계약을 그대로 두고 공급자만 바꿨고, 같은 일이 다시 생길 것이라 에이전트는 처음부터 **「호출 방법만 아는」 공급자 계층**을 따로 두었습니다. 업무 지식(프롬프트 · Tool · 권한)은 그 위에 있습니다.

사내 게이트웨이에는 네이티브 tool calling이 없습니다. 세션을 만들고 문장을 넣으면 문장이 나올 뿐입니다. 그래서 Tool 호출은 **「JSON만 출력하라」 규약**으로 구현했고, 이 방식은 공급자가 바뀌어도 그대로 동작합니다.

## 2. 코파일럿 의도 분류 — 하이브리드

```
질문 → 로컬 규칙으로 의도 1차 판정
     → 서버가 실명 · 고객사 · 문서번호를 마스킹한 뒤 LLM에 의도/필터만 요청
     → 실패하면 로컬 규칙 결과로 폴백
     → 조회 · 집계 · 문장 생성은 내부에서
```

- **원칙: 사내 데이터(고객사 · BOM · 단가 · 실명)는 외부로 나가지 않는다.**
- 일일 호출 예산, 429 수신 시 **10분 회로 차단기**, 실패 사유별 계측, 무응답률 측정.
- 폴백 조건 **11가지**(타임아웃 · 빈 응답 · 토큰 절단 · 스키마 위반 등)를 구분해 배지에 사유를 정직하게 표시. 한도가 소진되면 규칙 엔진이 확실히 처리하는 추천 질문을 띄움.
- 계측해 보니 폴백 품질이 낮은 진짜 원인은 모델이 아니라 **로컬 분류기가 정규식 몇 줄**이었다는 것. → 의도별 독립 점수제 + 슬롯 추출로 다시 짰습니다(무료 · 오프라인 개선부터).

## 3. 회의 녹음 → 회의록

```
① 업로드  — 브라우저 MediaRecorder(webm/opus) 원본 보관
② 녹취    — 화자 분리 + 구간 타임스탬프
③ 검수    — LLM이 회의 내용 · 결정 사항 초안 정리 → 후속 조치를 일정으로
```

- **세 단계를 독립 API로 나눈 이유**: 녹취는 실패 · 재시도가 잦고(네트워크 · 한도 · 긴 파일) 비용이 붙습니다. 원본만 서버에 남아 있으면 몇 번이든 다시 돌릴 수 있습니다. 한 번에 처리하면 실패할 때 회의가 통째로 날아갑니다.
- **STT 공급자 선정 기준은 데이터 위치**였습니다. 더 싼 해외 서비스가 있었지만, 설계변경 회의 음성은 마스킹이 불가능해서 **데이터가 국내에 머무는 서비스**를 골랐습니다.
- 자격증명은 소스에 넣지 않고 서버 설정 파일 · 환경변수로만 받습니다. API 응답에는 **설정 여부만** 나가고 키 원문은 절대 나가지 않습니다.

## 4. 입력값 자동 채움 — 「AI 생성」 표식

처음엔 AI 추천을 카드로 띄우고 「적용」 단추를 눌러 반영하게 했습니다. 실제로 써 보니 단추 하나가 더 있을 뿐이었습니다.

→ 결재선 · 견적서 · 일정 · 완료 보고 등 **AI가 추천하는 값은 기존 칸에 바로 채우고**, 그 구역 머리에 작은 **「AI 생성」** 꼬리표를 붙입니다. 구역이 처음 화면에 들어올 때 한 번만 짧게 강조합니다. 사람은 확인하고 고치기만 하면 됩니다. 꼬리표 모양은 UI 정본 한 곳에서만 정의합니다.

## 5. 문서 질의

문서 이름이 아니라 **문서 내용**에 대해 물을 수 있습니다. 문서함 · 사내 파일 서버의 문서에서 본문을 추출해 두고, 질문과 관련된 부분을 근거로 답하며 **근거 문서를 함께 보여 줍니다.** 절차서 질문에는 해당 조항을 근거로 붙입니다.
